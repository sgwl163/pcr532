# PCR532 Desktop

基于 **Tauri 2 + React + TypeScript + Rust** 的桌面应用基础项目，面向 Windows 开发。界面统一使用 **shadcn/ui + Tailwind CSS v4 + lucide-react**。

目前支持真实串口枚举、自动或手动连接 PN532、固件查询、连接心跳、ISO 14443A 卡片识别、授权已知密钥读取、Classic 有界字典密钥检测与分扇区读取，以及受限用户区单块/单页写入和读回校验。界面参考传统读卡工具：左侧设备与操作，主工作区为“扇区原始数据 / 字段分析”双栏，右栏还可切换“内容与日期”和“用户区写入”，下方保留操作日志。“专注数据”可收起设备操作栏。应用只面向 Tauri 桌面端，不提供浏览器运行模式。`get_app_info` 用于前后端通信诊断。

支持对已读取内容进行本地分析，包括 NFC 数据交换格式（NDEF）文本、链接、部分文本 MIME/日历记录和明确日期；也可按人工指定的 BCD 日期、Unix 秒（大/小端）、UTF-8 编码查看某个数据单元内的字节。日期显示不等于有效期识别，不上传数据。

应用现有未知密钥辅助功能是**有界字典检测**：只尝试内置或用户提供的候选密钥，不推导字典之外的密钥。尚未集成 nested、hardnested、Darkside 等密码分析恢复引擎，也不提供修改 UID、整卡克隆或通用解锁功能。`反编译/` 中的 C# 文件仅作为分析参考，不参与构建，也不会执行其中的原程序或更新器。

## 开发环境

- Node.js 24 LTS + npm（Vite 要求 Node.js 20.19+ 或 22.12+）
- Rust stable，目标 `x86_64-pc-windows-msvc`
- Visual Studio 2022 / Build Tools，包含“使用 C++ 的桌面开发”工具链及 Windows SDK
- Microsoft Edge WebView2 Runtime

首次安装依赖运行 `npm install`。已有锁文件时建议使用 `npm ci`。

## 启动

在项目目录中执行 `npm run tauri dev`，启动 Windows 桌面应用，支持前端热更新。`npm run dev` 仅供 Tauri 在开发时启动内部前端服务器，请通过桌面窗口使用应用。

桌面启动后自动读取系统串口列表，每 3 秒刷新。启动或检测到重新插入时，如果只有一个候选设备，会按当前波特率（默认 115200）自动尝试一次连接；有多个候选设备或未知型号时，手动选择串口并点击“连接并验证”。只有收到校验正确、芯片编号为 PN532 的固件响应后才显示已连接，并保留串口用于连接心跳；点击断开或退出应用后释放串口。手动断开后保持断开；失败后保留具体错误，可手动重试，避免每次轮询重复探测。

CH340、CP210x、FTDI 等是通用 USB 转串口芯片，列表标记为候选设备，不代表已经确认 PN532。程序仅自动探测唯一的候选串口，不遍历其他串口，也不会改写设备波特率。初始化只发送 UART 唤醒序列、清理未完成命令的 ACK、SAM 正常模式设置和固件查询，不读取卡片、不写卡、不进行认证或刷写固件。连接失败时可检查原软件是否占用串口、选择的波特率是否匹配，以及硬件是否处于 UART 模式。

### 卡片识别与只读数据

1. 连接并验证读卡器，将自有或已获授权的卡片放稳在感应区。
2. 点击“寻卡 / 重新识别”，显示 UID、UID 长度、ATQA（应答类型）、SAK（选择应答）及初步卡片类型。无卡是正常结果；程序不自动轮询卡片。
3. 对支持的类型选择起始地址和数量，点击“读取所选范围”。读取前会再次寻卡并核对 UID；换卡后请重新识别，UID 相同不代表是同一张物理卡片。
4. 数据显示为十进制地址和十六进制原始字节。部分读取失败会标为“读取未完成”，并保留已成功读取的行和错误位置；不能视为整卡数据。

支持范围：

- MIFARE Mini / Classic 1K / Classic 4K：按块读取，每块 16 字节，范围分别为 0–19、0–63、0–255。每次 1–16 块；必须手动输入 Key A 或 Key B 的一个已知 6 字节密钥（12 位十六进制）。此读取表单跨扇区继续使用同一密钥，认证失败即停止，不会尝试其他密钥；字典检测是另外的显式授权操作。扇区尾块中的密钥字节受卡片访问规则影响，返回值不代表可用密钥。
- Ultralight / NTAG 等 Type 2：仅初步识别为家族，尚未确认精确型号，因此保守限定为前 16 页（0–15），每页 4 字节，每次 1–16 页。
- ISO 14443-4 A 及其他未知 ISO 14443A 类型：仅显示识别信息，不读取数据。不支持 ISO 14443B、FeliCa 等其他协议。

所有类型均由协议响应初步判断，不能据此验证真伪或确认厂商型号。密钥输入没有默认值，提交后清空，不写入配置文件或日志；卡片信息和数据仅保留在当前窗口状态，清除结果、断开连接或连接失效后移除。

寻卡、读取、写入、固件心跳和连接操作共用执行队列及独占串口会话。操作期间暂停新的前端心跳和重复操作；每次结束后重新检查连接。串口超时或帧校验异常可能导致会话失效，需要重新连接，避免迟到响应影响后续命令。普通无卡和卡片认证失败与串口连接故障分别处理。

### 获取不到数据时的判断

主数据区顶部的“数据获取状态”始终保留，即使启用“专注数据”也能查看当前阶段和错误：

- “尚未建立可验证的设备连接”：先验证设备连接。浏览器打开的前端不能访问串口，会明确提示运行桌面程序；离线文件分析不受此限制。
- “已识别卡片，尚未读取原始数据”：UID 识别与用户区读取是两个步骤，选择范围并使用已获授权的认证信息读取。
- “已识别卡片，当前卡型仅支持识别”：当前尚未实现该卡型的数据读取协议，不代表认证密钥错误。
- “本次读取未获得数据（0 B）”：本次没有可解析字节，直接查看同一区域的读取错误；原始数据区不再显示为仍在等待操作。
- “已取得原始数据 …（部分结果）”：保留成功读取的内容和错误位置，仅表示本次范围，不能当作整卡。
- “离线文件已载入 …”：文件中已有字节，但没有文本或日期结果不代表空卡，也不代表已经解密房号、权限或有效期。

只读检查 `测试卡/正常的.dump`、`过期的.dump`、`VIP演示文件.dump` 的结果：均为 1024 字节 / 64 块的 Classic 1K 尺寸原始文件候选，标准内容分析均为 0 条记录、0 个明确日期。文件保持不变；文件名不是卡片业务状态的可靠证据。这些检查不涉及实卡认证，也不能据此确定实卡读取失败原因。

### 未知密钥：字典检测与读取

此功能是未知密钥恢复的第一阶段，不等于已实现任意卡片解密。卡型未知时先寻卡；仅初步识别为 MIFARE Mini / Classic 1K / Classic 4K 时开放检测。

1. 在左侧“密钥检测 / 字典”选择起始扇区与数量，默认仅检测 1 个扇区，也可选择全部 5 / 16 / 40 扇区。
2. 明确选择是否尝试内置 8 个常见密钥，或输入最多 64 个自定义候选密钥。每个为 12 位 HEX，使用空格、逗号、分号或换行分隔；去重后按顺序尝试。内置候选为 `FFFFFFFFFFFF`、`000000000000`、`A0A1A2A3A4A5`、`B0B1B2B3B4B5`、`D3F7D3F7D3F7`、`4D3A99C351DD`、`1A982C7E459A`、`AABBCCDDEEFF`。
3. 勾选卡片归属与测试授权后点击“开始字典检测并读取”。分别验证每个扇区的 Key A / B，成功认证才显示为命中；某个类型命中后不再尝试其他候选。失败不意味着密钥不存在，也不能证明卡片无漏洞。
4. 使用已认证密钥逐块尝试读取所选扇区，在数据表 A 显示原始数据。部分权限失败可尝试另一个已命中密钥；缺失、拒绝的块不补零。尾块返回的密钥字节不作为恢复依据。
5. 进度显示候选认证次数、完成扇区和命中数量。读取时使用命中密钥的再次认证不计入“候选认证”次数。点击取消后等待当前命令/重新激活序列返回；状态确认前仍显示运行中，不允许并行读写、断开或连接心跳。

后端共用独占串口锁；每次认证前关闭/打开射频场，重新识别并比较 UID、ATQA 与 SAK。仍不能凭相同标识证明是同一张物理卡。任务最长约 10 分钟（在命令边界检查），认证不匹配继续下一个候选，其他协议/通信异常停止。串口失效后不再发送重试、读取或释放命令。取消、异常或未命中都不能显示为完整读取；“完整”仅表示所选范围全部块已读取，不代表整卡或两个密钥都已获得。

自定义字典提交后清空输入；已命中密钥默认隐藏，可主动显示复制。候选密钥不进入日志、进度或文件，结果和数据仅保留当前会话，清除结果、重新寻卡、断开或连接失效后移除。内存中的 JS / IPC / Rust 字符串不保证安全擦除，不应视为受保护的密钥存储。

能力边界：

- 当前没有 nested / hardnested / Darkside 密钥推导，字典外的未知密钥不会被恢复，也不穷举 48 位密钥空间。
- [上游 MFOC](https://github.com/nfc-tools/mfoc) 的 offline nested 需要至少一个可用密钥，适用性取决于实际芯片；不是任意卡通用恢复。
- 原软件 `Form1.cs` 静态代码分别启动 `nfc-bin/mfoc.exe`、`mfocx64.exe`、`mfcuk.exe` 和 `libnfc_hardnested.exe`。本项目参考目录没有这些引擎的完整可构建源码或可验证运行环境，因此没有直接复制或运行原二进制，也没有把外部进程退出码当作密钥恢复成功。后续集成需要单独核对来源、许可证、Windows 构建和 PN532 串口兼容性。
- Type 2 密码、DESFire 等的认证机制不同，不套用 Classic 字典流程；永久锁定位不能通用解除。本功能不写卡、不更改访问条件或密钥。
- 当前仅完成模拟协议/状态/界面测试，尚未对实体卡验证射频复位、重复认证、命中读取、取消与拔插；历史固件连接实测不覆盖本功能。

### 离线文件与字段显示

- 点击“导入 .dump”，支持 320、1024、4096 字节的 Classic Mini / 1K / 4K 原始文件。左栏按扇区显示块地址、十六进制和 ASCII，顶部区分已载入长度与布局容量，不补齐缺失块。文件中的 UID 仅为布局候选，不代表实际射频识别。
- 右栏“数据分析”使用“数据项 / 位置 / 数据 / 说明”四列。点击位置可定位并高亮左栏对应字节；结构、已解码、待验证和未解码状态分别标记。扇区尾块的 Key A / B 字节默认在十六进制和 ASCII 中隐藏。
- “自动分析”只列通用结构和可确认编码的内容；手动选择“参考日期”后，才增加块 5、偏移 10–11 的大端二字节候选规则：年 = 2000 + (值 >> 9)，月 = (值 >> 5) & 15，日 = 值 & 31。`37 5F` 得到 `2027-10-31`，`35 21` 得到 `2026-09-01`。候选行优先显示，并明确标记字段用途待验证；不是自动识别的有效期。
- “专注数据”收起设备操作栏；“展开操作面板”恢复。内容与日历解析移到“内容与日期”页签，人工编码查看器保留在“数据分析”底部。
- 查看离线文件时禁用实卡寻卡、读取、字典检测与写入。关闭文件后才恢复设备操作，文件数据不会作为写前原数据。

### 用户区写入

1. 先识别卡片并完整读取待写块/页的原数据。数据表 A 可点击地址，在数据表 B 选择本次读取中可写的单元。
2. 输入精确长度的十六进制新数据；“载入原数据到编辑框”可用于修改已有数据。Classic 写入须单独提供一个已知 Key A/B，不复用读取时的密钥输入。
3. 点击“预览写入”，核对 UID、地址、原数据和新数据，勾选已授权、已备份及不可自动撤销的确认后，再确认写入。
4. Rust 后端重新检测 UID、实际卡片类型和容量，认证并比较原数据。原数据已变化则阻止写入；目标数据本就相同则不发送写命令。
5. 单次写入后立即读回校验。每次提交都会移除当前读取结果，下一次写入必须重新读取。

写入范围：

- Classic Mini / 1K / 4K：单块 16 字节。禁止制造商块 0、所有扇区尾块（含密钥和访问条件）及超容量地址。
- Type 2：仅单页 4 字节、用户页 4–15；写前读取容量标记（CC），要求有效 NFC Type 2 v1 标记、至少 48 字节用户容量及开放读写访问声明。UID、静态锁、CC、配置区均不开放；标记缺失、未格式化或访问受限的卡会被拒绝。CC 只声明访问方式，不保证目标页未被单独锁定，卡片拒绝命令时报告错误，不执行解锁。
- 不自动重试、不回滚、不批量写、不格式化；写入普通用户区仍可能破坏卡片应用数据。

**写入超时或连接中断不代表卡片未改变。** 如果未能读回确认，会明确显示“写入结果未确认”或“结果未知”；应先重新连接、识别并读取核实，不能直接再次写入。最近一次写入结果在断开、重新寻卡后保留，直到“清除结果”，避免丢失不确定结果。此记录不代表当前卡片。

### NFC 内容和日期

- Type 2 可点击“读取 NFC 数据（0–15 页）”，读取当前保守窗口并自动分析。解析从用户页 4 的连续数据开始，按照 TLV 和 NDEF 长度、消息边界及编码检查，不把任意字节猜成标准记录。长消息超出当前窗口时会提示数据不足，不能视为没有内容。
- 已支持的文本、链接、日历记录显示内容与来源地址；用户区可读文本中的 `YYYY-MM-DD`、`YYYY/MM/DD`、中文日期等按有效日历日期识别。日历记录中的日期属性保留字段来源。
- Classic 未实现完整的标准 NDEF 扇区映射，普通用户块只提取可读文本，不跨制造商块、扇区尾块或缺失地址猜测连续记录。原始字节始终保留。
- 日期与电脑读取时间分开。卡片不存在统一的开卡/到期/最后使用日期字段；私有、加密或厂商格式需要对应协议和授权密钥。发现一个日期并不能确认业务含义。
- “按指定编码查看字节”由用户明确选择单元、偏移和编码：BCD `YYYYMMDD` 严格校验真实日期；32 位无符号 Unix 秒按指定大小端显示 UTC；UTF-8 严格校验文本。人工解释仅是计算结果，不是已识别的卡片字段，不跨数据单元，也不会写卡。
- 分析不上传、不联网、不执行链接。清除卡片结果或断开连接会移除读取数据和分析结果；日志只保留最近 200 条当前会话状态，不保存密钥或数据内容。

**验证范围：**卡片功能通过模拟协议、状态与界面交互测试，尚未对实体卡片完成寻卡、认证、读取和写入回归。开发过程中未自动打开真实串口或写入实体卡片。下方 COM7 历史实测只涵盖读卡器连接。

### 驱动

CH340/CH341 型号使用 WCH 的 CH341SER 串口驱动。Windows 设备管理器正常出现 `USB-SERIAL CH340 (COMx)` 表示系统已识别串口；若 PN532 固件握手成功，则当前串口驱动已可用于本应用，无需另装专用 NFC 驱动。仅当设备管理器出现未知设备、黄色感叹号或驱动错误时，再通过 Windows Update 或芯片厂商官方渠道安装匹配驱动。本应用不运行反编译目录附带的驱动安装器。

本机验证结果：`COM7`，WCH 已签名驱动 `3.9.2024.9`，115200 baud，PN532 固件 `1.6`。该结果是当前机器的实测记录，不硬编码到应用状态；实际界面始终读取系统和设备响应。

“测试后端通信”只读取应用名称、版本、操作系统和处理器架构，不访问硬件。

### 反编译代码参考范围

只读核对 `反编译/PCR532-recovered/PN532CardReader/MifareOneTool/` 中的连接流程：

- `drvier.cs` 第 49 行调用 `driver/CH341SER.EXE`；第 263、270 行区分 CH340 驱动和 CDC 型号。这是原软件的驱动入口，不是本应用运行时依赖。
- `Form1.cs` 第 13626–13949 行的 `a(string, string)` 使用所选串口、8 数据位、1 停止位、无校验；发送以 `55 55` 开头的唤醒与 SAM 正常模式命令，并比对 ACK 和 SAM 响应。它还先调用第 13253 行附近的 `b(string, string)` 发送 `SETTING=9\r\n`；这是原软件特定的前置命令，当前 PN532 已实测无需该命令即可连接，因此本应用没有照搬。
- 本应用独立使用 Rust 串口库，保留唤醒、ACK 和 SAM 初始化，同时额外验证带校验和的 PN532 固件响应。由于当前 COM7 的完整握手和心跳已通过，没有盲目移植原程序的延迟、联网或驱动安装逻辑。

这些是对现有反编译文本的静态核对；未运行原软件、驱动安装器或更新器，也不依赖其 `libnfc` 外部程序。

## 界面开发约定

- 使用 `src/components/ui/` 中的 shadcn/ui 组件，按需添加，不一次性引入整套组件。
- 添加组件：`npx shadcn@latest add input select tabs`（示例；会生成本地组件源码及安装对应依赖）。
- 布局使用 Tailwind CSS 工具类；主题通过 `src/index.css` 中的语义变量统一调整。
- 图标从 `lucide-react` 按名称导入；纯装饰图标设置 `aria-hidden="true"`，仅图标按钮提供可访问名称。
- `@/` 指向 `src/`，已同时配置 TypeScript 和 Vite。
- Geist 字体随应用本地打包，中文回退到系统字体；运行时无需访问远程字体或 CSS 服务。
- `src/index.css` 保留亮色及暗色主题变量；当前页面使用亮色主题，尚未添加主题切换。
- shadcn 的共享样式已通过官方 `eject` 命令内联到 `src/index.css`，无需保留 CLI 的依赖树。组件源码仍可编辑、按需添加；升级共享样式需手动同步。

## 可选硬件回归

常规 `cargo test` 不打开串口。需要在本机验证真实设备时，在 PowerShell 中先将环境变量 `PCR532_TEST_PORT` 设置为设备管理器中对应的串口名（例如 COM7），可选设置 `PCR532_TEST_BAUD`（默认 115200），再运行 `cargo test --manifest-path src-tauri/Cargo.toml inspect_local_reader -- --ignored --nocapture`。请先在应用和其他软件中断开该串口。

此测试使用与应用相同的枚举、初始化、固件查询和连接管理代码，验证重复心跳、断开后的串口释放与重新连接，不发送卡片指令。物理拔出与重新插入需要在真实硬件上另行验证。
